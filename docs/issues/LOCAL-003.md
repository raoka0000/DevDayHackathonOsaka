# 写真の送信説明と分析・再試行の画面フローを作る

状態：下書き（GitHub未投稿）。LOCAL-003はGitHubのイシュー番号ではない。

追加要望（2026-11-07）：利用者がPCから3〜5枚程度の写真を選択する。以下は1枚前提の旧案で、複数選択・各プレビューと削除・各画像の検証、枚数と合計容量の上限、全写真の送信説明を含むフローへ更新する。暫定で1〜5枚とし、下限は確認待ち。どれか1枚が不正な場合は説明して送信しない。選択内容を変えた後に、以前の組に対する結果を表示・受け渡ししない。

## 背景・目的

`src/main.tsx` には画像選択とプレビューがあり、「外部送信・保存は行いません」と表示している。画像分析は未接続。利用者が送信内容を理解して明示的に分析を開始し、結果を確認して音楽生成担当に受け渡せるようにする。

## 対象範囲

- 選択 → プレビュー → 送信先と画像の取扱いの説明 → ユーザーの分析開始操作 → 分析中 → 印象と説明の表示／失敗・再試行、という画面遷移を用意する。任意の用途・希望の入力はLOCAL-002の契約に合わせる。
- `File` を分析要求に渡し、選択時だけでは送信しない。既存のJPEG/PNG/WebP・10 MiBという上限表示は、LOCAL-002で決めた実際の上限に合わせる。送信先や保存の説明は採用先の条件に合わせて正確に更新する。
- 分析結果を曲生成担当が受け取る明示的な境界として渡す。接続の操作・型は担当間で合意し、相手側が未完成なら結果表示と契約準拠の受け渡し点までとし、生成済みとは表示しない。
- 画像の変更・削除、再分析、遅延応答、画面破棄を考慮する。分析は現在のSongを変更しない。結果の無効化と通信キャンセル・応答の識別を行う。

## 対象外

音楽の生成とSongへの適用、コード・音符の組み立て、再生・MIDI変更、AI編集、写真の永続保存。

## 受け入れ条件

- [ ] 有効な画像を選択するとプレビューでき、選択だけでは通信しない。送信前に送信先・目的・アプリで保存しないこと・採用先の取扱いを確認でき、明示的な操作でのみ分析を開始する。
- [ ] 無効な画像・上限超過は分かりやすく表示し送信しない。分析中は状態が分かり、連打による重複送信を防ぐ。
- [ ] 成功時は対象画像の分析結果を提案として表示し、契約に沿って生成担当へ渡せる。固定サンプルやモックは実分析と区別される。分析では現在の曲・編集履歴・再生状態を無断変更しない。
- [ ] 失敗・タイムアウト・不正応答で理由と再試行方法が分かり、現在の曲と画像を保つ。別画像への変更・削除後に古い結果が表示・受け渡しされず、再分析の古い応答も新しい結果を上書きしない。
- [ ] 画像プレビューのURLを置換・破棄時に解放し、既存の固定サンプル、直接編集、再生、Undo、MIDI出力を維持する。

## 検証方法

- 自動：入力境界、二重送信、成功・失敗・再試行、画像変更と応答逆転を制御したテストで確認。Songが変化しないことと生成側に渡す結果を検証する。`npm run typecheck`、`npm test`、`npm run build`。
- ブラウザで選択→説明→分析→結果、無効入力、分析中の画像変更、失敗後の再試行、既存編集・再生・MIDIを操作確認する。実AIは認証が必要。公開URLで同じ操作ができた場合のみ確認済みと記録する。

## 優先度・依存関係

- 優先度：LOCAL-002の契約確定後。公開・固定再生の優先順位は維持する。
- 先行： [LOCAL-002](LOCAL-002.md) の契約・API。画面状態は契約に沿ったモックで並行開発できるが、実分析として完了するには実API・認証が必要。音楽生成担当との接続は別担当との合意・実装に依存する。
