# 開発手順・完了条件

## 着手と変更の単位

1. AGENTS.md、README、docs、対象コード、git status／git diffを確認する。
2. 受け入れ条件と対象範囲を決め、関連する課題・他担当との共有契約を確認する。既存の未コミット変更は保持する。
3. 既存の検証・編集関数を探して利用する。2か所目の同じ処理は共通化を検討し、将来のためだけの抽象化は追加しない。
4. 必要な実装と検証を行い、重要なルール・設計・起動手順が変わる場合のみ、関係する資料を最小限更新する。

ブランチを作る場合はcodex/を既定の接頭辞とし、利用者の指定を優先する。添付資料や別プロジェクトの指示は参考情報として扱い、対象固有の制約を確認して採否を決める。

## 環境とコマンド

初回準備・OS別の起動方法は[README](../README.md)を参照。依存の再現にはnpm ciを使い、依存変更時はpackage.jsonとpackage-lock.jsonを一緒に更新する。

| 目的 | コマンド |
| --- | --- |
| ローカル画面・API開発（同時起動） | npm run dev |
| 型チェック | npm run typecheck |
| 自動テスト（任意・今回の必須対象外） | npm test |
| 本番ビルド（型チェックを含む） | npm run build |
| ビルド済み画面の確認 | npm run preview |
| Workersでローカル確認 | npm run cf:dev |
| 公開 | npm run deploy |

現在Lint・フォーマッター・CIは未設定。存在しないコマンドを完了条件にしない。TypeScriptの設定対象は現在srcのみであり、テストはnpm testで実行する。

## 実装の約束

- 音楽の純粋処理はmusic.ts、音声の副作用はplayer.ts、画面の一時状態はコンポーネントに置く。依存方向と共有状態は[ARCHITECTURE.md](ARCHITECTURE.md)に従う。
- 入力エラーと予期しない失敗を区別し、利用者には次の操作が分かる日本語の結果を表示する。ログに写真・秘密情報・AIの入力全文を出さない。
- 外部入力は構造と値を検証し、型アサーションだけで安全とみなさない。ブラウザの検証だけでAPIの検証を省略しない。
- 依存・音源を追加する場合は公式資料とライセンスを確認する。実行環境と配布方法に合うものを選び、本番設定が増えたらPRODUCTION.mdに記録する。

## 完了条件と検証の選び方

今回のハッカソンでは時間を優先し、自動テストの追加・実行は必須にしない。既存テストは保持し、明示的な依頼がない限りテスト作業を進めない。アプリ変更は型チェック・ビルドを通し、変更した主要操作を確認する。ドキュメントのみの変更はリンク・既存実装との整合・git diff --checkを確認し、アプリ検証を省略した場合はその旨を記録する。

以下は必要時の確認観点であり、網羅的なテスト実施を完了条件にはしない。

| 変更対象 | 確認観点 |
| --- | --- |
| 音符・入力検証 | 境界外・非有限値・重複の拒否、和音・端点・空配列の許可 |
| 編集・再生成 | 元データの保持、対象外音符の維持、設定と音符のUndo、取消で不変 |
| MIDI | バイト列を解析し全Note On/Off・テンポ・拍子・終端を元データと照合 |
| Player | 手編集音符の予約、音声クロック、連打・resume待ち・停止時の古い演奏の破棄 |
| UI | 対象画面の操作、エラー、Undo、画面移動時の状態保持と停止 |
| AI（導入時） | 不正応答、タイムアウト、古い応答、適用・破棄・試聴での状態保護 |

実音声・外部DAW・公開URL・Windows実機の確認は、代替APIによるテストやローカル画面確認と分けて記録する。公開時の確認は[PRODUCTION.md](PRODUCTION.md)を参照する。

終了時は変更内容と実施した確認を会話で簡潔に報告する。作業記録のファイル作成は不要。未確認を成功にしない。

## ドキュメントの管理

共通ルールはAGENTS.md、構成と契約はARCHITECTURE.md、環境・検証手順はこの資料、本番設定はPRODUCTION.mdに集約する。READMEは導入と入口、CLAUDE.mdは共通ルールへの参照とする。
コードを見れば分かる一覧の重複を減らし、責務・安全条件・変更時に守る理由を記す。進捗表・予定・タスク管理は作成・更新せず、TASKS.mdの更新も不要。イシュー管理は明示的な依頼がある場合だけ行う。

参考にした別プロジェクトのCLAUDE.mdからは、ルールの集約、責務分離、型安全、秘密情報、重複防止、完了条件、用語統一を採用した。固有の認可関数・ID形式・日時API・DB制約・pnpm手順・既存データの削除方針はPhotoChordへ転用していない。追加のLint強制は実装していない。

`npm run dev` は `scripts/dev.mjs` が初回ビルド、Wrangler（内部8788）、Viteを管理する。Worker起動完了後にViteのURLを表示し、`vite.config.js` が `/api/` を転送する。画面はHMR、WorkerはWranglerの監視で更新する。Ctrl+Cで両方を終了する。内部ポート8788の競合やWorkerの起動失敗では画面も起動しない。画面だけの開発サーバーと本番ビルド確認を混同せず、`npm run preview` はAPIを起動しない。
