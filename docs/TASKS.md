# 3時間の実装タスク

企画と設計のみ準備済み。以下の実装は未着手。

## 0〜20分：公開と音の確認

- [ ] React + TypeScriptとCloudflareの最小構成を用意して公開する。
- [ ] 公開URLと検証済みの起動・ビルド・公開手順をREADMEに記載する。
- [ ] 固定の8小節データでブラウザから音を出す。
- [ ] 画像AIの利用可否・認証・画像送信を確認する。

認証が不足していても、サンプルと明示した曲で編集・再生の開発を進める。

## 20〜60分：曲データと直接編集

- [ ] Song・NoteEventと入力検証を実装する。
- [ ] コードから音符を生成し、8小節を再生する。
- [ ] 小節カード、コード選択、テンポ、伴奏パターンを実装する。
- [ ] 停止・再再生・再生位置表示を実装する。
- [ ] 直前の編集を元に戻せるようにする。

## 60〜95分：画像から初期生成

- [ ] 画像1枚の選択・検証・プレビューを作る。
- [ ] 画像AIから印象・理由・曲設定を生成する。
- [ ] AIの応答を検証し、曲データに反映する。
- [ ] 送信の説明、生成中・失敗・再試行、二重送信防止を用意する。

## 95〜130分：AI編集

- [ ] 自然言語と現在の曲から編集提案を生成する。
- [ ] 変更箇所・理由と、提案の試聴を実装する。
- [ ] 適用・破棄と元に戻す操作を接続する。
- [ ] 古い応答や不正な応答で編集中の曲が上書きされないようにする。

## 130〜155分：MIDIと検証

- [ ] 再生と同じ音符データからMIDIを出力する。
- [ ] 音符・テンポ・拍子・8小節の長さを別のMIDI対応ソフトで確認する。
- [ ] 型チェック・ビルド、入力検証と音符生成の必要な確認を実施する。
- [ ] 公開URLで画像→生成→直接編集→AI編集→MIDI出力を通す。
- [ ] API失敗、音源読み込み失敗、再生連打、停止を確認する。

## 155〜180分：発表準備

- [ ] 使用できる結婚式写真とサンプル曲を用意する。
- [ ] AI接続のある新規生成と、サンプルの両方でデモを練習する。
- [ ] 発表端末で公開サイトを開き、音声出力を確認する。
- [ ] 実装済み・未実装・制限をREADMEに反映する。

## 余裕があれば

メロディ、ピアノロール、音色変更、ドラム、複数画像、WAV出力。
MVPの編集・AI支援・MIDI出力より先には着手しない。

## 永続保存を追加する場合（MVP完成後）

[DB設計](DATABASE.md)に従い、以下を実装する。3時間の必須範囲には含めない。

- [ ] 開発用D1とローカルDB、マイグレーションを用意する。
- [ ] 匿名セッション・所有権確認・有効期限を実装する。
- [ ] 曲の保存・再読み込み・削除とrevisionによる競合検知を実装する。
- [ ] 他セッションのアクセス拒否と保存失敗時の再試行を確認する。
- [ ] 期限切れデータの削除と、本番用DBの分離を用意する。
