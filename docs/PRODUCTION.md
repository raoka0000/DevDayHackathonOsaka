# 本番設定・公開手順

## 現在の設定と確認状況

wrangler.jsoncが公開設定の正本。現在はdistをWorkers Static Assetsとして配信し、SPAのフォールバックを設定している。API用のmain、D1・R2・AIのバインディング、Cron、秘密情報は未設定。公開URLと本番での動作は未確認。

導入・デプロイのコマンドは[README](../README.md#cloudflare-workersへの公開)を参照する。cf:devとdeployはどちらも最初にビルドする。Workers上のローカル確認と、リモート公開は別の操作として扱う。

## 設定を変更するとき

- Worker名とログイン先アカウントを確認し、既存の別サービスを上書きしない。
- 公開設定・互換日付・バインディングを変更したらWrangler設定とこの資料を更新し、ローカルで確認してから公開する。
- ブラウザのVite開発サーバーにはWorkerのAPIが自動で生えるわけではない。API追加時はWorkerエントリー・ルーティング・開発時の接続方法を一緒に定義する。
- API追加時は/apiの要求が静的アセットのSPAフォールバックへ流れない構成を確認する。
- 保存導入時のDB分離・マイグレーション・所有権確認は[DATABASE.md](DATABASE.md)に従う。

## 秘密情報・外部サービス

AIは未接続であり、現在の固定サンプル版にAIキーは不要。導入時はローカルで.dev.vars、本番でWranglerのsecretを使う。キーはブラウザへ渡さず、VITE_変数、ソース、コミット、ログにも含めない。.gitignoreで除外されていてもGit差分に混入していないことを確認する。

外部サービスを導入した作業で、サービス名、用途、必要な設定名（値は記載しない）、登録・権限、費用と回数制限、障害時の挙動をここへ追記する。画像の送信先・目的・保存有無は画面の説明と一致させる。初期版では画像の永続保存を避ける。

## 公開時の検証

公開したURL、確認日、環境、確認した操作と未確認項目をTASKS.mdへ記録する。現在の固定サンプル版では、写真選択・編集・再生／停止／再再生・画面移動・Undo・MIDIダウンロードを確認する。AI接続後は画像入力→初期生成→直接編集→AI提案の試聴／適用／破棄→MIDI出力も通す。

発表端末で音声を実聴し、MIDIを外部ソフトで開いて確認する。サンプルと実際のAI分析の表示を区別し、送信説明・失敗時の再試行・編集状態の保護も確認する。確認できない認証・アカウント・課金条件は具体的に記録する。

設定変更前の公開バージョンを記録し、公開後に問題があればCloudflareのデプロイ履歴から復旧対象を確認する。DBやR2を導入した後は、アプリの復旧と保存データの復旧を分けて設計する。
